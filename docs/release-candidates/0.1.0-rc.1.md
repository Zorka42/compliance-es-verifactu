## Library verification

- `./gradlew --offline --no-daemon check compileKotlinMetadata compileKotlinIosArm64 koverXmlReportJvm koverVerifyJvm publishJvmPreview --continue --console=plain` passed (433 tasks; 92 executed in the final verification run). API baselines were updated and reviewed in a separate preceding `apiDump` invocation.
- Reports contain 189 JVM, 149 Android host, 162 iOS simulator and 162 macOS test executions: 662 total, with no failures, errors or skipped tests in those reports. Intel Apple binaries compile, but their tests do not run on this Apple Silicon host. Android device networking/provider behavior remains unverified.
- Core JVM coverage: 1,639 covered lines, 9 missed (99.45%); the existing 90% gate is unchanged.
- All 18 public-source manifest entries pass digest verification. The 15 pre-existing contracts were fetched again and matched their archived bytes; the three identifier additions retain provenance, including the explicitly extracted Interior factual snapshot.
- Arithmetic, identifier, receipt-date context, warning propagation, schema/Unicode/parser, response correlation and disposable loopback mTLS checks passed. Ordinary checks made no AEAT operational requests and used no existing taxpayer certificates.

## Local publication

`./gradlew --offline --no-daemon -PreleaseVersion=0.1.0-rc.1 publishAllPublicationsToLocalPreviewRepository` passed (444 tasks, 368 executed). It produced 40 publication directories for the five modules across root metadata, JVM, Android and configured Apple targets. The [artifact SHA-256 list](0.1.0-rc.1-sha256.tsv) records the actual local POM, module, JAR, AAR and KLIB files. Artifacts remain under `build/maven-repository` and are not committed as release binaries.

All five JVM modules contain binary/source/Dokka JARs, versioned POM metadata and `META-INF/LICENSE`. The independent POM-based consumer passed with:

```sh
./gradlew --offline --no-daemon -p samples/maven-consumer -PverifactuVersion=0.1.0-rc.1 run
```

That consumer compiles with Java 11 constraints and warnings as errors, including the new identifier/context entry points and existing overloads. Its local runtime was JDK 22; the repository CI separately tests the independent consumer on Java 11. The example's acceptance is from an injected synthetic transport with zero network calls. Dokka succeeds with its documented configuration-cache discard warnings.

## Real application evidence

The corresponding app-accounting implementation is commit `9ac803e57311e40d1c556c4b69c5458684910a67` on `codex/verifactu-durable-integration`. Its local profile consumes this checkout's JVM SNAPSHOT preview. The full app `check` passed both with the `verifactuRepository` profile (155 reported tests, no failures/errors, one pre-existing optional local-provider test skipped) and without it (145 reported tests, the same skip). Both include migration verification. The default app build does not depend on an unpublished artifact. The current UI issue action remains unconnected until complete fiscal configuration and annual numbering integration are supplied; receipt persistence does not yet imply correlated fiscal acceptance.

## Remaining gates

The [release plan](../release-plan.md) and Notion tasks track application activation, durable receipt correlation, source clarification, parser/API hardening, producer/declaration review, dependency/license audit and release-owner decisions. Known local limitations include zero-rate surcharge after 2024-10-01, unverified entity/K/L/M check characters and explicit EL/GR–XI/GB mapping assumptions.

Central namespace ownership, dedicated PGP signing identity, Central token and protected release secrets are still required for a separately authorized external release. AEAT test-environment calls, production reads for issued and received records, and personal certificate access remain separate operational tasks. This local candidate authorizes none of those actions.
